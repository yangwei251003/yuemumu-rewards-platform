# 产品需求说明（两窗口版）

## 1. 产品目标
让学生明确“做什么能得分、证据如何提交、何时到账、积分能换什么、奖品到哪里拿”；让教员能够审查规则与证据、识别异常、解释每笔分数；让企业能控制库存、预算和领取成本。
目标是成长与运营闭环，而不是增加打开次数。当前交付为本地可演示的产品候选，后续通过真实身份/资质/安全/运维验证才进入试用。

## 2. 端与入口
| 入口 | 使用人 | 核心工作 |
|---|---|---|
| `/` 学生H5 | 学生、体验访客 | 活动、任务、积分、项目、比赛、商城、成长、申诉 |
| `/admin/` 管理网页 | 教员、导师、运营、监察 | 管理审核、证据、账本、库存、预算、违规和报表 |
| `/admin/pickup/` 移动核销 | 企业领取人员 | 扫码或手输领取码、核验、交付与异常处理 |
| 微信小程序构建 | 后期真实学生 | 与H5共用Taro业务代码，认证/扫码/上传通过平台适配 |
| `/api/v1/` | 所有端 | 唯一业务服务；客户端不直连MySQL |

## 3. 功能范围与验收
| 模块ID | 学生侧 | 管理侧 | 核心验收 |
|---|---|---|---|
| M01 身份 | Demo登录、入门、身份状态 | 虚构名单、申请审批、角色范围 | 切换身份不跨账号泄漏；正式环境无Demo入口 |
| M02 活动会议 | 列表、报名、候补、取消、签到、完成任务 | 草稿发布、名额、签到、结束确认、批量审查 | 完整参与与单纯扫码区分，不能重复得分 |
| M03 实训技能 | 课程、测验、作品、技能要求 | 课程/题库、考核、教员签认、翼章 | 里程不是技能证书，飞行安全前置独立 |
| M04 宣传任务 | 认领、源文件和链接、角色贡献 | 验收、原创/授权、转化指标 | 一份作品只按主类别计分 |
| M05 项目 | 申请、团队、任务、里程碑、贡献确认 | 池额度、阶段验收、中止、复核 | 团队池不超发，分配精确守恒 |
| M06 竞赛 | 候选赛事、作品、团队、奖项、补证 | 白名单、赛级、证明、成员系数、晋级 | 仅补差额，撤奖/更正也能处理 |
| M07 积分 | 可用/冻结/待审/待结算/待追缴、明细 | 规则版本、补分申请、冲正、对账 | 余额可重建，禁止直接改分 |
| M08 奖励 | 27候选、筛选、心愿、详情、限兑、预约 | SKU/变体、采购、入库、批次、服务名额、图片 | 模拟库存与真实库存隔离 |
| M09 订单核销 | 确认、冻结、取消、待领取、动态码 | 备货、手机核销、退换、盘点 | 同事务、不可重复领取、故障可恢复 |
| M10 违规申诉 | 通知、陈述、申诉进度 | 证据、独立裁决、功能限制、复核、追缴 | 不自动无限封号，不公开羞辱 |
| M11 监察统计 | 自己档案、可选昵称榜 | 10%抽查、高风险全复核、月报、预算预警 | 指标有定义、权限与审计，有真实数据 |
| M12 平台维护 | 站内通知、隐私说明 | 导入、导出、备份、恢复、系统健康 | 私有文件不可公开直链，危险操作有门禁 |

## 4. 当前不做
不做现金充值/提现、微信支付、商家分账、短信群发、精准定位追踪、人脸识别、区块链、强制AI推荐、独立原生App、独立教员App。地图、学校SSO、微信订阅消息、付费图像API无凭据时不阻塞本地版本。

## 5. 关键旅程
学生报名并参加装调课→教员验收→按50分规则入账→学生兑换900分维修工具包→冻结积分/库存→工作人员核销→订单、钱包、库存、审计同时更新。另演示一笔拒绝自审、一笔比赛晋级差额、一笔领取码重复使用、一笔申诉撤销。

## 6. 通用界面状态
所有主页面具备加载、空、无权、错误、断网、过期及成功反馈；提交按钮防重但不能代替服务端幂等。后台分页/筛选/批量结果可追踪；批量批准不默认全选跨页。
演示模式页眉常显“模拟数据／内部演示”。缺失真实奖励图片时用自制插画并标示意图；不得用AI图冒充实际型号。

## 7. 非功能目标（设计目标，不是已测成绩）
在普通开发机本地演示20个并发会话；列表API预热后P95目标<800ms，页面冷启动目标<3秒（网络与机型须记录）；核心写入不重复、不超卖。首屏图像按需加载，无大体积循环特效。数据库重启不丢失已提交数据。所有指标报告测试条件与实测值。
