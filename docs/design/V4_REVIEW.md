## 失败如何保留

`evidence/v4/runs` 按时间建立独立命令日志、退出码JSON和浏览器报告。旧失败没有删除，也没有把多轮局部 PASS 相加。

- flow01 最初怀疑会话干扰；串行复现证实为空案卷渲染错误，已更正原因并修复。
- flow02 首次受本机默认 Python 缺少二维码解码库阻塞。使用已安装的依赖运行时后，以真实二维码完成独立解码。中断订单通过正常取消保留历史。
- commerce 首次停在旧“再选一次订单”的布局断言；V4已直接打开订单，改成断言正确订单编号。再次运行触发真实月度限次，换用另一虚构学生，未改变制度、余额或履约记录；第三轮完整通过。
- 导航脚本曾误把“重新载入过期表单”当作普通补证必有按钮，也曾匹配到 Taro 包装元素与真实输入两个节点。这些属于测试定位修正，保留业务字段和状态断言。
- 键盘空间初次检查发生在Taro转场途中，先修正等待稳定状态；随后确认真实底栏遮挡，补滚动避让后通过。一次H5构建命令误写包名前缀、没有匹配项目，虽退出0仍不计构建通过；以 h5-keyboard-r2 的实际761模块构建替代。
- 一次浏览器测试进程以 Windows 状态 3221226505 退出，没有报告，不计为通过。
