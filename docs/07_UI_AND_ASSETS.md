# 界面、内容与图片交付规范

## 产品视觉
品牌方向：蓝白、少量橙，专业校园低空科技，不做高饱和赛博朋克。学生端有成长感和可理解行动，管理端清晰密集、少装饰，核销端大字大按钮。学校和协会名按资料表；未给真实Logo用文字标识，不生成假校徽。
`packages/design-tokens/tokens.json`是颜色、间距、圆角、字号与动效基线，B维护。组件在各平台实现，不把AntD DOM控件拷进Taro。

## 学生信息架构
底部5项：成长、活动、项目、奖励、我的；项目内切换竞赛，技能从成长入口进入。首页第一屏：木能量可用/待处理摘要、成长进度、下一步可完成任务、已选心愿奖品差额；避免满屏广告条。详情先说明得到什么、需要做什么、证据、审核时限、地点，再报名。
积分明细清楚区分+入账、预占、核销、释放、冲正、到期，不能用一个负号让学生猜。订单显示可用/冻结变化与服务预约条件。申诉入口靠近相关决定，展示理由而不只“被拒绝”。

## 后台与移动核销
后台按工作流：待办→活动课程→内容任务→项目比赛→积分审批→奖励库存→兑换履行→违规申诉→监察报表→设置。
审批详情并排规则快照、证据、已发/拟发差额、前序审核者、利益回避；批量操作逐项返回。不能通过编辑表格直接修改余额。
核销三步：扫描/输码→预览确认→完成。展示本站点、奖品规格、数量、领取资格、必要身份信息。重复核销明确“已领取”，相机失败提供备用码，断网不假装核销成功，也不离线给库存记账。

## 组件与交互验收
Taro控件/轻量自绘优先，Taroify仅版本烟测通过再采用；管理端选AntD/ProComponents一套。主要触控目标建议≥44px，手机宽度360/390/430，后台1366/1440/1920实测；键盘可访问，颜色之外有状态文字；prefers-reduced-motion有降级。
数据提交不乐观显示“已到账/已领取”，必须以服务器结果为准。丢网、登录过期、冲突、额度不足、缺货、证据不合格各有可操作下一步。动效约150—250ms，仅作交互反馈；生产构建无无限渲染、无假loading。

## 图片制作顺序（B自主执行）
1. 清点用户授权Logo/校园/设备/真实奖品照片。
2. 使用可用内置图片工具生成原创Banner、分类图、成长徽章和服务体验卡；不硬编码付费图像API为前置。
3. 工具不可用或没有预算时，自绘原创SVG/矢量插图并做移动端兼容转换，或下载有明确许可的素材；不得只留下灰色占位块。
4. 实际品牌/型号商品必须用获授权实拍或供应商图。模拟展示可以用无品牌原创示意图，但图和文字同时标“示意图／模拟奖品”。正式入库前替换真实型号照片并验收。
5. 所有下载检查许可、robots/条款、尺寸和文件安全；不热链，不爬登录后平台、不绕防爬/收费、不伪造授权。

## 最低视觉交付
27个候选奖励都有有效缩略图和alt；至少6个原创类别/体验视觉，5级成长徽章，至少6种技能翼章，3类空状态。图片存文件、元数据存manifest，不用Base64塞API数据库。缩略图1:1，活动4:3或16:9；压缩目标单图≤160KB，详情可放大但按需加载。字体只引用许可可用的系统/开源资源，授权记录入档。
asset-manifest记录sourceUrl/owner/license/useScope/retrievedAt/sha256/aiGenerated/demoOnly/reviewStatus；批量写“已授权”不算审核。

## 无人机真实性
无人机视觉保持真实结构：穿越机四机臂、四电机、四旋翼，不画五旋翼；飞行体验须佩戴必要设备、受教员监督，插图不表达无需安全培训即可飞。概念插画不当作真实教学照片或飞行许可证明。

## B交付证据
保存学生首页、活动报名、积分账本、奖品、订单、后台审批、库存、核销、项目、竞赛、申诉的截图与移动尺寸说明；图片源文件/授权清单；所有主流程的加载、错误、空态截图。看图检查文本溢出、按钮遮挡、对比度和扫码区域；能构建不代表视觉合格。
